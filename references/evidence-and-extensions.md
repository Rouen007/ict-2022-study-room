# 证据、课程增量与 Macro／HTF 选学

## 当前覆盖如何确认

按需查询 `courseData.json` 的集数、原稿路径和关键帧，以及 `lesson-evidence.json` 的 claims；不要在每次请求中全量加载全部课程。

2026-10-25 整理时，本地有37集原稿、62张关键帧；仅 Ep.03、22、29 的所列部分字幕完成当前核读摘要。六个 Macro 观察窗口和 HTF 补充仍待具体原课核验。新增材料后以实际JSON为准，不沿用这些数量宣称完整性。

## 归因与可观察证据

| 内容类型 | 使用条件 |
| --- | --- |
| 原稿引文 | 能定位具体视频版本、集数、时间和原文；自动转写仍可能有误，不能仅靠中文字幕或旧摘要确认原话。 |
| 原图观察 | 已实际看图，记录截图来源和时间；图片存在或分辨率高不代表图注正确。 |
| 主模型核读摘要 | 已核读对应片段，标为摘要而非逐字引文；推断需列出支持证据和限制。 |
| 训练规则／合成练习 | 说明模型、policyVersion及模拟假设；不冒充课内原案例。 |
| 旧稿／新增笔记／选学归纳 | 未满足证据要求时保持待核验，不因写入JSON或接入页面自动升级。 |

日内结构变化不自动意味着多日反转；扫损、位移、MSS、订单块交付变化与SMT分别记录。价格经过某高低点，不能单凭K线证明止损数量、机构身份或操纵意图。

## 新增2022课程要点

1. 从 `courseData.json` 定位准确的 `sourcePath` 与 videoId，读取相关片段，必要时核对原片或截图。保留 No-Rant 剪辑版身份。
2. 在 `references/lesson-evidence.json` 增加核读摘要。每条记录需要稳定id、seconds、timeStr、sourcePath、sourceSHA256、sourceExcerpt、attribution、status与frameIds；既有记录是格式参考，不能复制其他集的证据当本集出处。
3. 当前 `transcript_checked` 只表示该字幕片段已核读。`sourceExcerpt` 必须精确匹配该时刻的解析片段，timeStr与seconds一致，源hash匹配该原稿。原稿有改动时重新核读并解释变化，不能只更新hash使检查通过。
4. 图片用 `references/frame-manifest.json` 的显式frameId或构建后的稳定frameId关联。无对应图则保留空frameIds，禁止按数组位置或相邻时间猜配。图注独立保持视觉核验状态。
5. 涉及新增教学内容时补充适用条件、失效或反例、对既有规则的作用及适当练习；不将单个成功案例提升为胜率结论。
6. 需要更新App时按工程维护文档重建；纯核读与问答无需重建。

No-Rant、原版与B站中配可能采用不同剪辑。未核对跨版本时间映射时，只提供B站分集链接，不复制秒数并宣称精确直达。

## Macro与HTF选学

维护源仍为 `framework.json` 的 `macroWindows`、`htfEvolution2023`。`framework_extensions.py` 只做时间解析、时长及训练窗口交集计算；不判断交易方向、胜率或真实成交。

- 新增Macro使用稳定id、time、session、focus、evidenceStatus=pending与sourceRefs。时钟按 America/New_York，格式HH:MM；结束须晚于同一当地日期的开始，窗口时长分别计算。
- 显示“观察窗口”“与训练新开仓时段的交集”“不新增交易的部分”。交集仅满足时间条件；不能覆盖sessionPolicy、自动取消既定风险约束或改变练习评分。
- 2023／2024的年份与官方归属需要具体原课出处。当前未建立对应扩展原稿库，不能用官方视频标题、检索结果或他人总结确认六个窗口的准确规则。
- HTF偏向保持可失效的条件路径。未有统计证据时不宣称顺势期望收益更高，也不把全部逆向信号归为弱回调。
- Macro观察与交易所实际开闭市、数据发布、竞价流程分别记录。交易所页面只支持它说明的市场机制，不支持Macro的方向或年份归属。

**当前实现边界**：扩展编译器仅接受pending。以后获得原课证据时，先建立可复核的扩展片段记录与校验路径，再升级证据状态；不得直接改为verified绕过校验。选学内容无需等同于2022基础课，也不计入2022已核验覆盖数。

## 证据不足时的交付

写明本次已核读的来源与时段、仍缺的原文或图、可以支持的结论及待验证项。缺某材料时继续处理不依赖它的部分；不反复扩大采集窗口，也不以工程验收替代教学核读。
